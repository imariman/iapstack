# Deploy IAPStack with Coolify

[`compose.yaml`](compose.yaml) is a Git-based Coolify Docker Compose application. It
builds IAPStack from the repository, creates a private PostgreSQL service, runs the
migration as a one-shot service, exposes only the API through Coolify's HTTPS proxy,
and keeps the worker private. PostgreSQL data lives in a named persistent volume.

> [!IMPORTANT]
> IAPStack is in early development and is not ready for production use. Use an
> isolated app and provider-sandbox credentials.

## Cost and account requirements

Self-hosted Coolify is free and does not require a Coolify Cloud subscription, but it
requires a Linux server that you operate and pay for. Coolify Cloud currently starts
at USD 5 per month for two connected servers, and you still supply and pay for the
server that runs IAPStack. There is therefore no provider-funded, permanently free
IAPStack environment here unless you already own suitable always-on infrastructure.

A Mac mini can be a laboratory host through a supported Linux machine or VM, but a
public store-webhook endpoint also needs continuous uptime, public DNS, and ports 80
and 443 reachable from the internet. A small VPS is usually the simpler test target.

The Compose definition uses Coolify magic variables to generate a stable PostgreSQL
password and two 64-character hexadecimal protection keys. PostgreSQL and the worker
have no public port mapping. The API's generated or custom domain terminates TLS at
Coolify's proxy.

## Deploy

1. Install self-hosted Coolify on a server, or create a Coolify Cloud account and
   connect your own server.
2. In a project and environment, select **New → Public Repository** and enter
   `https://github.com/imariman/iapstack`. Use a GitHub App or deploy key for a fork
   that is private.
3. Select the branch to test and set:

   - **Build Pack:** `Docker Compose`
   - **Base Directory:** `/`
   - **Docker Compose Location:** `/deploy/coolify/compose.yaml`

4. Save the resource and review the parsed services. For the `api` service, keep the
   domain generated by `SERVICE_URL_API_8080`, or assign a custom domain using the
   form `https://iapstack.example.com:8080`. Coolify uses port 8080 inside the
   container while serving normal HTTPS externally.
5. In Environment Variables, set `IAPSTACK_BOOTSTRAP_ADMIN_KEY` to a newly generated
   secret before the first deployment:

   ```sh
   openssl rand -base64 32
   ```

   Coolify generates the independent `SERVICE_PASSWORD_64_METRICS` value used to
   protect `/metrics`; do not replace it with the administrator bearer.

6. Deploy and wait for `postgres`, `migrate`, `api`, and `worker`. The completed
   migration container is intentionally excluded from Coolify's overall health
   evaluation.
7. Verify `https://<assigned-domain>/readyz`, open `/dashboard/`, and use the
   bootstrap key to create and securely store the first durable administrator key.
8. Empty `IAPSTACK_BOOTSTRAP_ADMIN_KEY` in Coolify and redeploy. The generated
   protection and fingerprint keys must remain stable across deployments.

Automatic Git deployments are useful later, but keep them disabled during provider
sandbox setup so a branch push cannot unexpectedly replace the test backend. Before
using real data, configure off-server backups for the PostgreSQL volume and test a
restore.

## Cleanup

Deleting the application stops its containers. Explicitly remove its PostgreSQL
volume if the test data is no longer needed, and verify the server has no remaining
IAPStack containers or volumes. Volume deletion is permanent.
