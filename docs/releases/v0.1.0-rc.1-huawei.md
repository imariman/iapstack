# v0.1.0-rc.1 Huawei AppGallery Sandbox Gate

Run this gate against one immutable candidate on a real Huawei device. The automated
Compose fixture cannot replace provider-managed account, billing, renewal, refund,
revocation, and notification behavior.

Recheck Huawei's official [sandbox testing guide](https://developer.huawei.com/consumer/en/doc/hmscore-guides/sandbox-testing-0000001050035039),
[subscription behavior](https://developer.huawei.com/consumer/en/doc/HMS-Plugin-Guides-V1/subscription-func-0000001126667693-V1),
and [`InAppPurchaseData` reference](https://developer.huawei.com/consumer/en/doc/HMSCore-References/inapppurchasedata-0000001050137635)
immediately before execution.

## Environment

1. Register the exact package, signing certificate, and build version in AppGallery
   Connect. Configure one non-consumable lifetime product and one monthly subscription.
2. Add the signed-in HUAWEI ID as a sandbox tester and wait for configuration propagation.
3. Install the candidate APK on a real Huawei device with current HMS Core.
4. Confirm the harness reports both `Test account: Eligible` and
   `Sandbox APK: Eligible` before opening checkout. Stop if either check fails or the
   sandbox notice is absent, because a real charge may otherwise occur.
5. Record only the non-secret application ID, APK version, device model, OS version,
   and HMS Core version.

Huawei's sandbox renewal timing and maximum renewal count may change. Confirm the
current provider documentation and use a fresh tester/product state where needed.

## Required scenarios

| Evidence name | Required observation |
| --- | --- |
| `lifetime_purchase` | One valid lifetime purchase grants access and creates one logical transition. |
| `lifetime_duplicate_restore` | Two restore submissions preserve the same projection version and logical event count. |
| `subscription_initial` | The initial purchase grants access and reports automatic renewal enabled. |
| `subscription_renewal` | One compressed renewal advances the authoritative validity period exactly once. |
| `subscription_cancellation` | Stopping renewal records cancellation-at-period-end while access remains through expiration. |
| `subscription_expiration` | Final authoritative expiration denies access. |
| `subscription_grace` | Grace keeps access only through `graceExpirationTime`. |
| `subscription_refund` | Refunding only the latest fee preserves the provider-defined access and renewal semantics. |
| `subscription_revocation` | `cancelTime` immediately denies access and creates one revocation transition. |
| `invalid_signature` | Tampered signed data is rejected without an observation, entitlement, or outbox write. |
| `wrong_application_binding` | Valid evidence in another application scope is rejected without a write. |
| `wrong_product_binding` | A mismatched claimed product is rejected without a write. |
| `wrong_customer_binding` | A customer different from signed `developerPayload` is rejected without a write. |
| `duplicate_notification` | Repeating one signed notification creates one inbox identity and no duplicate transition. |
| `missed_notification_reconciliation` | Omitting notification delivery and running authoritative reconciliation converges exactly once. |

Huawei distinguishes cancellation-at-period-end, immediate revocation, and fee refund.
Test them separately. Negative evidence may be constructed only in an ephemeral
operator session; never put source purchase bodies, signatures, tokens, customer
identifiers, or notification bodies into the release record or shell history.
