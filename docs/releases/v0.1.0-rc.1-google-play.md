# v0.1.0-rc.1 Google Play Internal-Testing Gate

Run this gate with a signed app bundle installed from a Google Play internal-testing
track, a license tester, active Play Console products, Android Publisher credentials,
and authenticated Pub/Sub RTDN delivery. A sideloaded debug APK does not satisfy the
provider gate.

Recheck Google's official [billing test guide](https://developer.android.com/google/play/billing/test),
[subscription lifecycle guide](https://developer.android.com/google/play/billing/subscriptions),
and [RTDN reference](https://developer.android.com/google/play/billing/rtdn-reference)
immediately before execution.

## Environment

1. Configure the exact package name, one non-consumable one-time product, and one
   auto-renewable subscription base plan in Play Console.
2. Enable the grace, account-hold, and pause behaviors needed by the test matrix.
3. Configure matching IAPStack catalog data, Android Publisher service-account
   credentials, Pub/Sub topic/subscription, push audience, and push principal.
4. Install the candidate from the internal-testing link and use a license-testing
   account with Google's test payment instruments.
5. Record only the non-secret package name, app version, device model, Android version,
   and Play Store/Play Billing runtime version.

## Required scenarios

| Evidence name | Required observation |
| --- | --- |
| `non_consumable_purchase` | One completed purchase grants access exactly once. |
| `non_consumable_duplicate_restore` | Two owned-purchase submissions preserve one projection version and logical event. |
| `subscription_initial` | The initial subscription grants access and is acknowledged after the durable IAPStack transaction. |
| `subscription_renewal` | One accelerated renewal advances the authoritative period and creates one transition. |
| `subscription_cancellation` | Voluntary cancellation retains access until the authoritative expiration. |
| `subscription_expiration` | Expiration denies access after the effective period. |
| `subscription_grace` | A declined renewal in grace keeps access only through the authoritative grace state. |
| `subscription_account_hold` | Account hold denies access and recovery restores it through authoritative state. |
| `subscription_pause` | Pause denies access for the paused interval and resume restores it exactly once. |
| `subscription_refund` | A provider refund produces the expected authoritative access decision. |
| `subscription_revocation` | Revocation immediately denies access and creates one transition. |
| `pending_purchase` | A pending purchase remains unresolved and is not acknowledged or granted. |
| `post_commit_acknowledgement` | A completed unacknowledged purchase is acknowledged only after entitlement and outbox commit; a failed commit leaves it retryable. |
| `invalid_purchase_token` | An invalid token is rejected without an observation, entitlement, acknowledgement, or outbox write. |
| `wrong_application_binding` | A token from another package/application scope is rejected without a write. |
| `wrong_product_binding` | A mismatched claimed product is rejected without a write. |
| `wrong_customer_binding` | A mismatched opaque account binding is rejected without a write. |
| `duplicate_notification` | Replaying one authenticated RTDN push creates one inbox identity and no duplicate transition. |
| `missed_notification_reconciliation` | Omitting RTDN delivery and running authoritative reconciliation converges exactly once. |

RTDN indicates that provider state changed; it is never treated as the complete state
snapshot. Confirm each notification path performs the Android Publisher query before
changing access. Never place purchase tokens, order IDs, Pub/Sub bodies, or customer
bindings in the release record.
