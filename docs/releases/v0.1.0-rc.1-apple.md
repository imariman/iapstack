# v0.1.0-rc.1 Apple App Store Sandbox Gate

Run this gate with App Store Connect products, an Apple Sandbox Account, real
App Store-signed StoreKit 2 transactions, App Store Server API sandbox credentials,
and App Store Server Notifications V2. Xcode-local StoreKit transactions are signed
by Xcode and do not satisfy the backend release gate.

Recheck Apple's official [sandbox testing overview](https://developer.apple.com/documentation/storekit/testing-in-app-purchases-with-sandbox),
[test-environment comparison](https://developer.apple.com/documentation/storekit/testing-at-all-stages-of-development-with-xcode-and-the-sandbox),
and [server-notification testing guide](https://developer.apple.com/documentation/storekit/testing-app-store-server-notifications)
immediately before execution.

## Environment

1. Configure the exact bundle ID, one non-consumable product, and one auto-renewable
   subscription in App Store Connect.
2. Configure matching IAPStack catalog data, App Store Server API credentials, Apple
   trust roots, and the sandbox Notifications V2 URL.
3. Use a real Apple device with Developer Mode and an Apple Sandbox Account. TestFlight
   is acceptable only when the same sandbox account controls the required lifecycle
   scenarios.
4. Mint a fresh short-lived customer session and use its canonical UUID as the
   StoreKit `appAccountToken`.
5. Record only the non-secret bundle ID, app version, device model, OS version, and a
   concise StoreKit/App Store sandbox runtime description.

The repository-owned harness removes repeated bearer and JWT handling. Copy
`scripts/apple-sandbox.env.example` to the gitignored `scripts/apple-sandbox.env`,
store the dedicated application bearer with
`./scripts/apple-sandbox keychain set-application-key`, and launch a fresh customer
session with `./scripts/apple-sandbox run`. Use
`./scripts/apple-sandbox restore-idempotency` for the consecutive restore gate.

After configuring the complete sandbox Version 2 notification URL in App Store
Connect, store the matching `.p8` once with
`./scripts/apple-sandbox keychain set-app-store-key /absolute/path/AuthKey.p8` and run
`./scripts/apple-sandbox notification-test`. The command passes only when Apple's
recorded delivery result is `SUCCESS`; it does not print the signed payload or test
notification token.

## Required scenarios

| Evidence name | Required observation |
| --- | --- |
| `non_consumable_purchase` | One App Store-signed non-consumable purchase grants access exactly once and is finished only after the server commit. |
| `non_consumable_duplicate_restore` | Two restore submissions preserve one projection version and logical event. |
| `subscription_initial` | The initial subscription grants access with the authoritative expiration and renewal state. |
| `subscription_renewal` | One accelerated renewal advances the authoritative period and creates one transition. |
| `subscription_cancellation` | Disabling auto-renew records cancellation-at-period-end while retaining access until expiration. |
| `subscription_expiration` | The final expired status denies access after the effective period. |
| `subscription_billing_retry` | A simulated failed renewal enters billing retry without inventing an allowed grace interval. |
| `subscription_grace` | With Billing Grace Period enabled, access remains allowed only through Apple's signed grace expiration. |
| `subscription_refund` | An approved sandbox refund produces the authoritative refunded state and expected access decision. |
| `subscription_revocation` | A revoked transaction immediately denies access and creates one revocation transition. |
| `invalid_signature` | Tampered JWS evidence is rejected before any observation, entitlement, or outbox write. |
| `wrong_application_binding` | Valid evidence submitted under another IAPStack application is rejected without a write. |
| `wrong_product_binding` | A mismatched claimed product is rejected without a write. |
| `wrong_customer_binding` | An `appAccountToken` different from the authenticated customer is rejected without a write. |
| `duplicate_notification` | Replaying one Notifications V2 signed payload creates one inbox identity and no duplicate transition. |
| `missed_notification_reconciliation` | Omitting notification delivery and running authoritative reconciliation converges exactly once. |

Apple sandbox can accelerate renewals, simulate billing failures and grace periods,
disable auto-renew, and test refunds. Use a fresh account/product state when one
scenario would contaminate another. Never place a signed JWS or transaction ID in the
release record.
