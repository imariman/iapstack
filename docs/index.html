How it works

From store evidence to delivered entitlement.

IAPStack sits between app stores and your backend. Every purchase travels the same route, and every step is durable and observable.

Purchase route

Store evidence to delivered entitlement
  1. Store

    Apple, Google and Huawei adapters receive receipts and server notifications.

  2. Verify

    Evidence is checked against the authoritative store API before anything changes.

  3. Access

    Transactions become store-neutral entitlements: allowed, denied or unresolved.

  4. Deliver

    Your backend queries a versioned API and receives signed webhooks.

Less glue. More control.

A clean boundary

Credentials and purchase data stay with you.

IAPStack owns the hard parts of purchase lifecycle management, while every secret, receipt and decision lives in your PostgreSQL.

  • Verify at the source. Store adapters validate evidence with Apple, Google or Huawei.
  • Project durable access. Lifecycle evidence becomes store-neutral entitlements.
  • Deliver to your app. A versioned API and signed outbound webhooks.

Local first

Up and running on your machine.

Start the complete local stack with Docker Compose. Generate local-only secrets, launch the services and check readiness.

~/iapstack — zsh
$ git clone https://github.com/imariman/iapstack.git
$ cd iapstack
$ export IAPSTACK_POSTGRES_PASSWORD="$(openssl rand -base64 32)"
$ export IAPSTACK_PROTECTION_ACTIVE_KEY_ID="local-1"
$ export IAPSTACK_PROTECTION_KEYS="{\"local-1\":\"$(openssl rand -base64 32)\"}"
$ export IAPSTACK_PROTECTION_FINGERPRINT_KEY="$(openssl rand -base64 32)"
$ export IAPSTACK_BOOTSTRAP_ADMIN_KEY="$(openssl rand -base64 48)"
$ export IAPSTACK_METRICS_BEARER_TOKEN="$(openssl rand -base64 48)"
$ docker compose -f deploy/compose.yaml up --build -d --wait ✓ Container iapstack-postgres Healthy
✓ Container iapstack-api Healthy $ curl --fail http://127.0.0.1:8080/readyz
{"status":"ready"}
