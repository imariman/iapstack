# Support

IAPStack is prerelease, community-maintained software without a support SLA. The
maintainer and contributors respond on a best-effort basis.

## Before opening an issue

Check the documentation that matches the problem:

- [README and local quick start](README.md)
- [Operations and dashboard guide](docs/operations.md)
- [HTTP API guide](docs/api-v1.md)
- [Deployment target guides](deploy/README.md)
- [Flutter package guides](sdk/flutter/iapstack/README.md)

Search [open and closed issues](https://github.com/imariman/iapstack/issues) for an
existing answer. If the behavior looks like a reproducible defect, use the bug report
form. Use the feature request form for a proposed capability or change in behavior.

Include the IAPStack commit or version, provider, sandbox or production environment,
deployment method, expected and actual behavior, and minimal reproduction steps. Share
the smallest useful log excerpt after removing API keys, credentials, purchase
evidence, customer identifiers, database URLs, and other sensitive data.

Questions about a cloud provider's account, billing, outage, or store-console policy
may need to be raised with that provider. Self-hosted deployment, data recovery, and
incident response remain the operator's responsibility.

Suspected vulnerabilities must be reported privately as described in
[SECURITY.md](SECURITY.md), not through a public support issue.
